# DreamBench-SWE

- **Measurement object:** Whether later software tasks correctly use or suppress non-inferable evidence from earlier sessions, with the resulting code changes scored by hidden executable oracles.
- **Closest predecessor:** MemoryArena and WorldMemArena connect memory to later action, while SWE-bench supplies executable software tasks; DreamBench-SWE crosses them into controlled repository-continuation memory-hygiene traps. The later Agent Memory Bench (coding agents) provides a complementary real-repository comparison.
- **Decisive evidence:** v2 uses 60 traps × 3 seeds = 180 S3 cells per complete condition. In the successor, B0 scores 21/180, B5 82/180, the typed-plus-raw reference probe 83/180, and one pinned Mem0 literal-storage configuration 97/180; all available memory-versus-B0 comparisons reject after Holm correction.
- **Score ceiling:** The evidence supports DreamBench-SWE as a discriminating executable profile benchmark, not mechanism superiority among memory-bearing conditions, equivalence, or broad product generality.
- **Strongest confounder:** Synthetic fixture repositories and one pinned wake/judge/model stack; filesystem isolation is not network isolation, and memory configuration plus the coding harness remain part of the treatment.
- **Remaining gap:** Real production repositories and cross-model/cross-harness transfer; C9/C10 lack B0 headroom and therefore do not support broad rejection/abstention claims.
- **Genealogy:** It decomposes “does retained experience help later action?” into whether retained evidence remains current, scoped, authorized/relevant, and correctly suppressed when it should not be used; `map_delta=early_signal`.
