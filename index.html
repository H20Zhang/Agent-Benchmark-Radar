Current thesis

More benchmarks are not the same as better measurement.

Two evaluations can both be called “agent memory” or “agentic RAG” while testing different scientific objects. The useful comparison starts by separating capability, environment, and evaluation protocol—and then asking which variables make the leaderboard incomparable.

Benchmark Map

The map is intentionally not a taxonomy of paper titles. Every benchmark is located by three independent axes.

01 · CapabilityWhat must the agent do: retrieve, update state, resolve conflict, learn a workflow, join data, execute code, verify, recover, or adapt?
02 · EnvironmentWhere does competence have to work: conversation history, trajectory archive, websites, static corpora, multiple DBMSes, code sandboxes, or mixed structured/unstructured workspaces?
03 · ProtocolWhat is observed and scored: final answers, executable outputs, intermediate hops, trajectories, repeated trials, latency, tokens, tool calls, or judge-based rubrics?

Coverage Gaps

The most useful Radar output is often not another benchmark—it is identifying which research conclusion current evaluation cannot support.

Closed-loop memory value

Past-history QA is not yet the same as proving that memory improves future action under matched context and compute budgets.

Lifecycle cost

Ingestion, memory writing, indexing, retrieval, retries, tool calls, and judge cost can move between stages while headline accuracy stays unchanged.

Harness sensitivity

Model, tools, hints, stopping, retries, prompts, and evaluator choices often change the score enough to defeat component-level attribution.
