## 本月判断：benchmark validity 本身正在从背景条件变成测量对象

八月最重要的共同变化，不是三个方向都出现了更复杂的任务，而是**评价开始显式控制“什么状态、什么接口、什么 verifier 让一个分数成立”**。Memory 把 recall 拆成 current-state correctness、episode integrity、downstream action utility 与 lifecycle safety；RAG 把 corpus snapshot、packing/search harness 和 corpus feedback 纳入有效性边界；Data Agents 则把 executable success 拆成 verifier reliability、research improvement 与 anti-gaming。这个变化比单个 leaderboard 上涨更重要，因为它决定我们能否把系统进步归因到真正的能力，而不是环境、接口或评分器。

## Agent Memory：retrieved evidence 不再等价于有效记忆

[PAST-Bench](../../benchmarks/past-bench.md) 用 persistence on/off 直接测跨 episode 经验是否改变后续行动；[StateMemBench](../../benchmarks/statemembench.md) 与 [membench (staleness)](../../benchmarks/membench-staleness.md) 把 current state 和 superseded state 分开；[DreamBench-SWE](../../benchmarks/dreambench-swe.md) 与 [SCALE-QA](../../benchmarks/scale-qa.md) 又进一步要求系统恢复真正约束当前任务的 source-of-truth / operative episode。与此同时，[SP-Mem](../../benchmarks/sp-mem.md)、[InjecMEM](../../benchmarks/injecmem.md)、[Utility Under Attack](../../benchmarks/utility-under-attack.md) 和 [The Compaction Cliff](../../benchmarks/compaction-cliff.md) 把 consent、恶意写入、防御 utility 与压缩后的约束保真度纳入 lifecycle。

这些工作共同支持一个更严格的测量分层：**evidence visibility → state validity → episode integrity → later behavior**。但它们仍不能证明某一种 memory representation 普遍更优；representation、write/update policy、verification 与 consumer policy 必须继续用 matched intervention 拆开。

## RAG / Agentic Retrieval：corpus 与 harness 成为 score 的组成部分

[The Recall Trap](../../benchmarks/recall-trap.md) 说明更高 file recall 在固定 packing 协议下甚至可能对应更差的 downstream repair；[The Commercial Tax](../../benchmarks/commercial-tax.md) 把 license、query format、index construction 与 cost 绑定到 retrieval number；[BrowseComp-Plus_CM](../../benchmarks/browsecomp-plus-cm.md) 则在尽量固定 question、agent 与 search interface 后替换 corpus，直接暴露 substrate 对任务难度的影响。随后 [KBGym](../../benchmarks/kbgym.md)、[Snapshot Compatibility Audit](../../benchmarks/snapshot-compatibility-audit.md) 与 [RAG Collapse](../../benchmarks/rag-collapse.md) 又把 corpus 从静态输入推进成可编辑、会增长、会形成 feedback 的状态对象。

因此八月更可靠的结论不是“agentic search 已经优于静态 retrieval”，而是：**任何 retrieval / planning gain 都必须绑定 corpus snapshot、evidence surface、interface、budget 与 downstream contract。** Live、动态或可写语料如果没有版本化，也会让 benchmark drift 被误读成模型进步。

## Data Agents：能执行只是 correctness 链条的中间层

[data-eng-bench](../../benchmarks/data-eng-bench.md) 的 verifier/environment 修复说明隐藏测试本身会制造或抹去成功；[AI4AI-Bench](../../benchmarks/ai4ai-bench.md) 用 proxy exploration → source patch → clean-start final run 约束对 proxy 的过拟合；[DeltaML-Bench](../../benchmarks/deltaml-bench.md) 则把真实研究仓库改进与 anti-gaming audit 绑定。补齐 [MLE-bench](../../benchmarks/mle-bench.md) / [MLE-Dojo](../../benchmarks/mle-dojo.md) 谱系后，ML-engineering 分支已经能区分“代码能跑”“实验分数提高”和“改动在受控最终协议下仍成立”。

这里仍有一个关键空缺：这些 benchmark 主要把 **research / execution correctness** 做得更严，却还没有系统解决 BI / warehouse 里的 **business truth**。未来 Data Agent 评价需要同时保留 executable verifier 与 semantic oracle，而不是让 SQL/code execution 代替业务正确性。

## 研究设计含义

九月最有价值的 benchmark 设计，不是继续把更多能力塞进一个总分，而是做 **matched state intervention**：固定 actor/model、工具表面、数据/语料 snapshot、judge/verifier 版本和总预算，只改变一个 memory policy、retrieval policy 或 orchestration boundary；同时分别报告 evidence exposure、state correctness、execution correctness 与最终 task/business outcome。这样才能回答“为什么赢”，而不只是“谁赢了”。
