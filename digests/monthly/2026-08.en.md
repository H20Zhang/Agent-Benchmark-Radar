## Monthly judgment: benchmark validity is becoming a measured object rather than a background assumption

The most important common change in August is not simply that all three areas gained harder tasks. Evaluation increasingly controls **which state, interface, and verifier make a score valid**. Memory splits recall into current-state correctness, episode integrity, downstream action utility, and lifecycle safety; RAG brings corpus snapshots, packing/search harnesses, and corpus feedback inside the validity boundary; Data Agents separate executable success from verifier reliability, research improvement, and anti-gaming. This matters more than a single leaderboard gain because it determines whether progress can be attributed to capability rather than environment, interface, or scorer behavior.

## Agent Memory: retrieved evidence is no longer equivalent to valid memory

[PAST-Bench](../../benchmarks/past-bench.en.md) uses a persistence-on/off intervention to test whether cross-episode experience changes later action. [StateMemBench](../../benchmarks/statemembench.en.md) and [membench (staleness)](../../benchmarks/membench-staleness.en.md) separate current state from superseded state. [DreamBench-SWE](../../benchmarks/dreambench-swe.en.md) and [SCALE-QA](../../benchmarks/scale-qa.en.md) go further by requiring recovery of the source of truth or operative episode that actually constrains the current task. In parallel, [SP-Mem](../../benchmarks/sp-mem.en.md), [InjecMEM](../../benchmarks/injecmem.en.md), [Utility Under Attack](../../benchmarks/utility-under-attack.en.md), and [The Compaction Cliff](../../benchmarks/compaction-cliff.en.md) bring consent, malicious writes, defense-induced utility loss, and constraint preservation after compaction into the lifecycle.

Together these records support a stricter measurement stack: **evidence visibility → state validity → episode integrity → later behavior**. They still do not establish a universally superior memory representation. Representation, write/update policy, verification, and consumer policy need matched interventions rather than package-level attribution.

## RAG / Agentic Retrieval: corpus and harness become part of the score

[The Recall Trap](../../benchmarks/recall-trap.en.md) shows that higher file recall can coincide with lower downstream repair success under a fixed packing protocol. [The Commercial Tax](../../benchmarks/commercial-tax.en.md) binds retrieval numbers to license, query format, index construction, and cost. [BrowseComp-Plus_CM](../../benchmarks/browsecomp-plus-cm.en.md) holds the question, agent, and search interface as fixed as possible while swapping the corpus, exposing how the substrate itself changes task difficulty. [KBGym](../../benchmarks/kbgym.en.md), [Snapshot Compatibility Audit](../../benchmarks/snapshot-compatibility-audit.en.md), and [RAG Collapse](../../benchmarks/rag-collapse.en.md) then move the corpus from a static input to a state object that can be edited, grow, and form feedback loops.

The defensible August conclusion is therefore not that agentic search has already beaten static retrieval. It is that **any retrieval or planning gain must be bound to the corpus snapshot, evidence surface, interface, budget, and downstream contract**. Live, dynamic, or writable corpora also need versioning so benchmark drift is not mistaken for model progress.

## Data Agents: execution is only an intermediate layer of correctness

The verifier/environment repair in [data-eng-bench](../../benchmarks/data-eng-bench.en.md) shows that hidden tests can create or erase apparent success. [AI4AI-Bench](../../benchmarks/ai4ai-bench.en.md) uses proxy exploration → source patch → clean-start final execution to constrain proxy overfitting, while [DeltaML-Bench](../../benchmarks/deltaml-bench.en.md) couples improvement in real research repositories with anti-gaming audits. With the lineage through [MLE-bench](../../benchmarks/mle-bench.en.md) and [MLE-Dojo](../../benchmarks/mle-dojo.en.md) restored, the ML-engineering branch can distinguish “the code runs,” “the experiment score improved,” and “the improvement survives a controlled final protocol.”

One important gap remains. These benchmarks make **research / execution correctness** substantially stricter, but they do not yet systematically solve **business truth** in BI and warehouse settings. Future Data Agent evaluation needs both executable verifiers and semantic oracles rather than treating SQL or code execution as a substitute for business correctness.

## Research-design implication

The highest-value September benchmark design is not another aggregate score containing more capabilities. It is a **matched state intervention**: hold the actor/model, tool surface, data/corpus snapshot, judge/verifier version, and total budget fixed; change one memory policy, retrieval policy, or orchestration boundary; then report evidence exposure, state correctness, execution correctness, and final task/business outcome separately. That turns “who won?” into the more important question: “why did it win?”
