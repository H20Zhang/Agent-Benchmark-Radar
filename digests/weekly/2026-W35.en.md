## Weekly judgment: the evaluation target is splitting from aggregate answer/recall scores into intervenable state and verification coordinates

The important change this week is not benchmark count. All three areas are decomposing an over-aggregated headline score. Memory separates stale/superseded state, episode integrity, and downstream action utility; RAG turns harness, corpus snapshot, and corpus-state feedback into measurement objects; Data Agents continue splitting “the code runs” into research integrity, verifier reliability, and long-horizon experimental improvement. The common requirement is that **a system score must be tied to which state changed, which evidence was used, and which execution contract was actually satisfied.**

## Agent Memory: from “was it remembered?” to state governance + episode integrity

[Agent Memory Bench (coding agents)](../../benchmarks/agent-memory-bench-coding.en.md) and [membench (staleness)](../../benchmarks/membench-staleness.en.md) place downstream action utility and stale-memory failure in the same weekly window. [The Compaction Cliff](../../benchmarks/compaction-cliff.en.md), [MPBench](../../benchmarks/mpbench.en.md), [InjecMEM](../../benchmarks/injecmem.en.md), and [Utility Under Attack](../../benchmarks/utility-under-attack.en.md) then separate compaction, privacy/forgetting, and adversarial lifecycle integrity. [DreamBench-SWE](../../benchmarks/dreambench-swe.en.md) and [SCALE-QA](../../benchmarks/scale-qa.en.md) further separate evidence visibility from reconstruction of the operative episode/state. Multiple independent records now justify state validity as an evaluation coordinate, but they do not establish a universal advantage for any memory representation.

## RAG: corpus and harness become validity boundaries

[BrowseComp-Plus_CM](../../benchmarks/browsecomp-plus-cm.en.md) shows that deep-retrieval claims must be bound to an independently constructed corpus and harness. [KBGym](../../benchmarks/kbgym.en.md), [RAG Collapse](../../benchmarks/rag-collapse.en.md), and [Snapshot Compatibility Audit](../../benchmarks/snapshot-compatibility-audit.en.md) treat the corpus itself as state that can be edited, contaminated by feedback, or naturally grow. [LitReview Arena](../../benchmarks/litreview-arena.en.md) adds expert judgment to deep-research evaluation. Headline recall or answer accuracy is therefore insufficient to identify retriever quality without corpus state, evidence exposure/use, and the downstream protocol.

## Data Agents: from executable success to research integrity

[AI4AI-Bench](../../benchmarks/ai4ai-bench.en.md) and [DeltaML-Bench](../../benchmarks/deltaml-bench.en.md) turn improvement of real ML research code into long-horizon executable tasks while explicitly resisting proxy overfitting or specification gaming. This week also restores [MLE-bench](../../benchmarks/mle-bench.en.md) and [MLE-Dojo](../../benchmarks/mle-dojo.en.md) to the canonical genealogy, connecting fixed competition tasks and interactive experiment environments to research-repository improvement. The important shift is not merely that agents write better code: evaluators must separate **real improvement, environment variance, and exploitation of the scoring contract**.

## Research-design implication

The highest-value matched control for the next benchmark generation is to expose system-package state as freezeable interventions: for Memory, freeze actor and source archive while changing write/update/verification/consumer policy; for RAG, freeze corpus snapshot, retriever interface, and budget before changing search policy; for Data Agents, freeze environment image, verifier version, and compute budget before changing orchestration. That is what moves a leaderboard from “who won?” to “why did it win, and at which validity boundary?”
