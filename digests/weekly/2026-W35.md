# 2026-W35 Benchmark 周报

**周期：** 2026-08-24—2026-08-30（ISO week 35）  
**精确合成时间：** 2026-08-31 08:37 +08:00  
**支撑的 Radar 接受记录：** 20（`browsecomp-plus-cm`、`delta-ml-bench`、`ai4ai-bench`、`agent-memory-bakeoff`、`membench-staleness`、`agent-memory-bench-coding`、`memtrapbench`、`statemembench`、`compaction-cliff`、`injecmem`、`utility-under-attack`、`mpbench`、`kbgym`、`snapshot-compatibility-audit`、`litreview-arena`、`rag-collapse`、`mle-bench`、`mle-dojo`、`dreambench-swe`、`scale-qa`）  
**置信度：** medium-high

## 本周判断：evaluation target 正在从“答案/召回”拆成可干预的状态与验证坐标

本周最重要的变化不是 benchmark 数量，而是三个方向都在拆掉一个过度聚合的总分。Memory 开始把 stale/superseded state、episode integrity 与 downstream action utility 分开；RAG 开始把 harness、corpus snapshot 与 corpus-state feedback 当作测量对象；Data Agents 则把“代码跑通”继续拆成 research integrity、verifier reliability 与长程实验改进。共同点是：**系统得分必须绑定到哪个状态被改变、哪个证据被使用、哪个执行合约被满足。**

## Agent Memory：从“是否记住”转向 state governance + episode integrity

[Agent Memory Bench (coding agents)](../../benchmarks/agent-memory-bench-coding.md) 与 [membench (staleness)](../../benchmarks/membench-staleness.md) 把 downstream action utility 和 stale-memory failure 放到同一周；随后 [The Compaction Cliff](../../benchmarks/compaction-cliff.md)、[MPBench](../../benchmarks/mpbench.md)、[InjecMEM](../../benchmarks/injecmem.md) 与 [Utility Under Attack](../../benchmarks/utility-under-attack.md) 把 compaction、privacy/forgetting 与 adversarial lifecycle integrity 分开。最新的 [DreamBench-SWE](../../benchmarks/dreambench-swe.md) 和 [SCALE-QA](../../benchmarks/scale-qa.md) 又把“可见 evidence”与“恢复正确 operative episode / state”拆开。多项独立记录已经足以说明 memory evaluation 需要 state validity 坐标，但它们仍不支持某一种 memory representation 的普适优势。

## RAG：corpus 与 harness 本身成为 validity boundary

[BrowseComp-Plus_CM](../../benchmarks/browsecomp-plus-cm.md) 显示同一类 deep-retrieval claim 必须绑定独立 corpus/harness；[KBGym](../../benchmarks/kbgym.md)、[RAG Collapse](../../benchmarks/rag-collapse.md) 与 [Snapshot Compatibility Audit](../../benchmarks/snapshot-compatibility-audit.md) 则把 corpus 视为会被编辑、反馈污染或自然增长的状态对象。[LitReview Arena](../../benchmarks/litreview-arena.md) 进一步把专家判断引入 deep-research evaluation。因而 headline recall/answer score 已不足以单独解释 retriever quality；需要同时报告 corpus state、evidence exposure/use 与 downstream protocol。

## Data Agents：从 executable success 转向 research integrity

[AI4AI-Bench](../../benchmarks/ai4ai-bench.md) 与 [DeltaML-Bench](../../benchmarks/deltaml-bench.md) 都把“改进真实 ML 研究代码”变成长程执行任务，并显式压制 proxy overfitting / specification gaming。本周同时补齐 [MLE-bench](../../benchmarks/mle-bench.md) 与 [MLE-Dojo](../../benchmarks/mle-dojo.md) 的谱系位置，使 ML-engineering 分支能从固定 competition task、交互式实验环境一路比较到真实 research-repository improvement。这里的关键不是 agent 更会写代码，而是 evaluator 要能区分**真实改进、环境偶然性与对评分器的利用**。

## 研究设计含义

下一轮 benchmark 最有价值的 matched control，是把“系统 package”拆成可单独冻结的状态变量：Memory 固定 actor 与 source archive，只干预 write/update/verification/consumer policy；RAG 固定 corpus snapshot、retriever interface 与预算，再改 search policy；Data Agent 固定 environment image、verifier version 与 compute budget，再改 orchestration。只有这样，benchmark 才能从“谁赢了”推进到“为什么赢、在哪个边界上赢”。

**Durable Benchmark Map：** 本周已接受记录提供了多项 reinforcement / split / revision evidence，但没有新的跨独立工作证据要求再次改写当前 defining chains；周报只做闭周期合成，不向主 README 回灌滚动 synthesis。
