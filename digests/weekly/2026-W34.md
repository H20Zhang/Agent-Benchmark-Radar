# 2026-W34 Benchmark 周报

**周期：** 2026-08-17—2026-08-23（ISO week 34）  
**精确合成时间：** 2026-08-24T00:44:47Z（UTC）  
**支撑的 Radar 接受记录：** 10  
**置信度：** medium

本周的可审计接受记录不是十篇论文构成的一条“总趋势”。更准确的变化是：RAG 出现了两组有独立支撑的 validity 结论，Memory 的评价对象继续分裂为不同因果问题，而 Data Agents 只有一个 evaluator-reliability 早期信号。

## RAG：检索分数必须绑定“找到了什么”与“后来是否有用”

[The Recall Trap](../../benchmarks/recall-trap.md) 在固定 file-slot repair 协议中观察到 recall 提升与修复成功下降，[The Commercial Tax](../../benchmarks/commercial-tax.md) 则表明 license、query format、index construction 与 cost 会改变同一 embedder 数字的部署含义。两项独立记录共同支撑 `retrieval-harness-validity`：headline retrieval score 只能说明给定 corpus、packing、接口、预算与 downstream protocol 下的系统表现，不能自动归因为 retriever component quality。

另一组独立记录把“覆盖”拆细：[MAPLE](../../benchmarks/maple.md) 测同一论文跨 aspect 的持续可检索性，[VisDocAgentBench](../../benchmarks/visdocagentbench.md) 在统一 top-10 合约下比较静态与迭代视觉检索，[WANDR](../../benchmarks/wandr.md) 则把 live-web 的开放集合发现和逐条核验合在一起。这强化了 `structured-evidence-coverage`，但三者环境不同，不能互相当 leaderboard 复现。

## Agent Memory：同一周出现的是坐标分裂，不是单向成熟

[PAST-Bench](../../benchmarks/past-bench.md) 用 persistence on/off 直接问“记忆是否因果改善后续行动”；[SP-Mem](../../benchmarks/sp-mem.md) 把 personalization、consent、exact-value exposure 与 cost 放进同一生命周期协议；[MemFuseBench](../../benchmarks/memfusebench.md) 则诊断跨来源 linking、causal fusion、conflict 与 provenance。它们说明 memory quality 已不能由 recall 一个轴概括，但每个坐标目前各只有一项本周接受信号，不能写成已确立趋势。

## Data Agents：先审计 evaluator，再解释 leaderboard

[data-eng-bench](../../benchmarks/data-eng-bench.md) 的 Snowflake verifier / environment 修复暴露了一个可复现性边界：隐藏测试与执行环境本身会制造或抹去成功。尚无公开的完整修复后 leaderboard rerun，因此本周只能记为 `executable-verifier-reliability` 的 `early_signal`，不能推断模型或 scaffold 排名已经改变。

## 研究设计含义

下周最有价值的比较不是再加一列总分，而是公开 matched controls：RAG 同时报告 evidence exposure、evidence use 与 downstream success；Memory 使用有/无持久状态或有/无风险状态的配对干预；Data Agent 在固定 environment image 和 verifier version 后重跑。这样才能把“系统在某协议下更强”推进为可归因的组件证据。
